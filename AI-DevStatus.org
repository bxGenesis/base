* Key Design Decisions
- =emacs+py+tex= for =.gitignore=, not =emacs+py=: it keeps =*_archive= (=AI-WorkPlan.org_archive=) and
  does not ignore =lib/=, which =provisioners= tracks (=lib/bash/=).
- Stage 2 decisions (2.1): the fto files of a gitGroup directory are deferred (to be done
  differently); existing platforms are not converted --- a platform is updated by re-installing it
  and re-running its CBMs, so the old layout phases out; =bisos-web= and =cliGui= stay without =base=.
- The gitGroup link is relative (=command()= with =ln -sfn=), because the pbd's =symLink()= always
  makes an absolute one.
- 3.1.2 (2026-11-24, user decisions): each CBM leaf carries its own bootstrap sbom,
  =cbmBootstrap-sbom.pcs=, so CBMs become self-contained and distributed. Phased: Phase 1 pip only
  (=bisos3=), the clones central (bisos.common's registry, missing ones added there); Phase 2, after
  gitist is merged with sbom (bisos.sbom has no git kind: =reposSeed.py= is a stub), the clones in
  the leaves. The status is a host fact, so =/bisos/var/cbm/<leafRel>/cbmProc.status=, keyed
  without the vcMode, with a =leaf= link back (implemented in bisos.capability); =cbmProc.control=
  stays in the leaf. A missing central clone goes in bsip4's =bxRepos-gitist.pcs=.
- Permissions policy (2026-11-24, user): bystar is in group =bisos=; Raw-BISOS installs everything
  =bisos:bisos= and group-writable, so bystar can overwrite it. Implemented by
  =bisosBaseDirsSetup.sh= (bxGenesis/provisioners): =2775= and =default:group::rwx= on =/bisos=,
  =/var/bisos=, =/bxo=, =/de/run=. The later steps run as =sudo -u bisos=, whose umask is =0022=, so
  the default ACL is the only source of group write: fix a deviation at its step, never by a
  =chmod -R= afterwards. A tool that chmods its own files (=egg-info=, tarball modes) escapes it.
  The group itself reaches the walk only through a new session: =rawBuildContainer.cs=
  (bisos/raw) runs a container down+up between =rawBisosBase= and =rawBisosCBMs=, the fix for
  261123's (c) and (g), cause A of 3.1.2.4; since =67d21af= (2026-11-25, the user) its recreate +
  build recipe also ends with down+up.
- Paths (2026-11-25, user; 3.2.2): =/bisos/git/bxRepos= is canonical. =/bxRepos= is a hand-made
  convenience link that a fresh install does not have, so nothing installed or committed (code, a
  =cbsSpec=, a =package.json= =file:= dependency, a committed link) names it, nor one vcMode
  (=/bisos/git/auth/=, =/anon/=). A Raw-BISOS rebuild has no =/bxRepos= at all (user, 2026-11-25), and
  none of the raw chain, the container build or bisos.common creates it (checked); so a VM run finds
  what still uses it. The check: the 3.2.2 Results.
- VNC: =vncPassword set= hashes in a throw-away container of
  the image, so a tool missing there cannot be fixed in the running instance.
